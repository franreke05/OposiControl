### Screen 09 — Content Upload

- `CURRENT: PASS_WITH_GAPS`. Integrated into `integration/mobile-finish` (originally `feature/mobile-content-upload` / `9eea7da`, `3c09713`).
- `CONTENT_IMPORT_READY_FOR_REAL_CLIENT_DATA: NO`.
- Runtime, live Supabase/RLS compatibility, asynchronous processing and immersive resources remain pending.
- Duplicate handling and atomic publication: **implemented** — publishing a batch is ONE atomic RPC (`admin_import_lote_preguntas`, all-or-nothing) with duplicate detection (`admin_import_lote_duplicados`); there is no `parcial` state (a batch ends `importado` or the publish fails as a whole). The historical candidate at `supabase/canonical/content_import_atomicity_candidate_v1/` is superseded. Deploy order: migration M10 FIRST in MAIN, then Ktor.
- **2026-09-04 desktop redesign**: `!compactLayout` now renders the new `features:imports` module (`ImportScreen`/`ImportWizardScreen`) instead of `ContentUploadScreen`; `compactLayout` (mobile) is byte-for-byte unchanged. Publication is atomic on both layouts; the compact screen no longer warns about partial publication (its copy and its Skip action now match the desktop screen: Skip uses `SkipContentImportStagingUseCase`, without completeness validation). No parser/staging/RPC change; reuses the same `domain` use cases as the legacy screen.

### Screen 10 — Estado del sistema

- `2026-10-15`: en escritorio `AppRoute.System.Status`, `Diagnostics` y `Settings` abren el hub de Sistema en la pestaña Estado (por defecto). El hub tiene tres pestañas: Estado, Administradores, Auditoría. Preferencias y Seguridad se retiraron. La pantalla suelta de estado solo existe en la vista estrecha, desde Ajustes. Réplicas, alertas, cuota de Supabase y versión desplegada salen de Prometheus con consultas fijas en el servidor; si Prometheus no responde se dice, nunca se pinta verde.

- `CURRENT: CONNECTED / OBSERVABILITY_V1`. Route `AppRoute.System.Status`, independent from the legacy `AppRoute.System.Diagnostics` and opened from Settings.
- `KtorSystemStatusRepositoryImpl` consumes the authenticated `GET /api/v1/admin/estado-sistema` snapshot. Ktor and Supabase retain their real health signals; CPU/RAM come from Node Exporter through Prometheus; latency is Ktor HTTP p95 over 5 minutes; errors are observed HTTP 5xx over a complete 24-hour window.
- Missing, invalid or unreachable Prometheus series stay `null` and render as «No disponible»; a measured zero renders as zero. Worker, mobile crashes and queue remain unavailable until they have real sources. `updatedAt` is the actual snapshot timestamp.

## Navigation and scope notes

- Desktop entry: `main()` (`composeApp/src/jvmMain/.../main.kt`) → `OposiControlAdminApp` (`App.kt`) → `AppRoot`; source exposes the administrative `AdminSection` set. `DesktopModerationRoot` is an unused pass-through wrapper (dead code, not deleted in this phase) — it is not the real entrypoint.
- Mobile entry: `MobileContentRoot → MobileContentScreen/MobileAdminPanel`; the mobile panel exposes the operational subset plus the Dashboard quick action to `AppRoute.Content.Imports` for Screen 09.
- The source also contains `SETTINGS`, but the required product registry here intentionally covers the 17 requested sections and does not count Settings as one of them.
- `AppRoute.System.Status` (Screen 10) remains separate from the legacy `AppRoute.System.Diagnostics` route. It is connected through `KtorSystemStatusRepositoryImpl`; unavailable sources remain explicit and are never replaced with fabricated zeros.
- Runtime visual reachability remains `NOT_VERIFIED`.
