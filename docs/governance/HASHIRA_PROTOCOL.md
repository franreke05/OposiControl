# Hashira Protocol

Cada tarea tiene un Hashira owner y al menos un reviewer distinto. El owner entrega evidencia, no una conclusión autosuficiente. Los cross-domain changes se enrutan según `.claude/HASHIRA_ROUTING.md`; contradicciones bloquean el supuesto afectado; los riesgos abiertos permanecen abiertos hasta evidencia de resolución.

Para esta fase: Documentation implementa la memoria; Architecture revisa la coherencia; Quality revisa la validación; los dominios afectados quedan como reviewers de handoff. Ningún Hashira modifica Kotlin, DB o despliegue sin autorización específica.
